# Deploying the WinterArc beta

This is the public-beta version (`WinterArcBeta` branch). It has its **own** API, database, web app,
keys and Android app, completely separate from the personal WinterArc.

```
browser / Android app ──► Vercel (web app, from WinterArcBeta)
                              │  /api/*  proxied to ──► Render (API, from WinterArcBeta) ──► MongoDB Atlas (beta database)
                                                              ├─► Resend (emails)
                                                              ├─► Backblaze B2 (Drop files)
                                                              └─► Web Push
```

Domain names come later: use the free `*.onrender.com` / `*.vercel.app` addresses for now and put the real
ones into the same settings when you have them.

## 1. MongoDB (beta database)
Reuse your Atlas cluster but give the beta its **own database name**, e.g.
`mongodb+srv://USER:PASS@cluster.mongodb.net/winterarc_beta?retryWrites=true&w=majority`.
Use a database user that only has access to that database. Network Access: `0.0.0.0/0` (Render's free plan has no fixed IP).

## 2. Render (API)
1. Render → **New → Blueprint** → this repo, branch **WinterArcBeta**. It reads `render.yaml` and creates `winterarc-beta-api`.
2. Fill in when asked (or later under Environment). Required to start: `MONGO_URI`, `FRONTEND_ORIGIN`, `APP_URL`
   (both = your Vercel address, e.g. `https://winterarc-beta.vercel.app`), `ADMIN_EMAIL` (your email).
3. Check `https://<your-service>.onrender.com/api/health` → `{"status":"ok","mongoConnected":true}`.

## 3. Vercel (web app)
1. Vercel → **Add New → Project** → this repo → **Production Branch: WinterArcBeta** (Settings → Git).
2. If your Render address is not `winterarc-beta-api.onrender.com`, change the `destination` in `vercel.json`.
3. Deploy. Open the site: you should see the sign-in screen.

## 4. Email (Resend) — needed for verification and password reset
1. resend.com → create an account → **API Keys** → create one → put it in Render as `RESEND_API_KEY`.
2. Until you own a domain, leave `EMAIL_FROM` unset: Resend only lets the default sender (`onboarding@resend.dev`)
   deliver to **your own** email address. To email testers you must verify a domain in Resend and set
   `EMAIL_FROM="WinterArc <hello@yourdomain>"`.
3. Without `RESEND_API_KEY` the links are only printed in the Render logs (fine for a first smoke test).

## 5. First admin and invite codes
1. Sign up in the app with the email you put in `ADMIN_EMAIL`. You need an invite code for that first sign-up: create one
   from your computer with the beta database connection string:
   `MONGO_URI="..." npm run invite:create -- --count 1 --note "me"`.
2. Confirm your email (link in the message). After that you are an admin.
3. More codes for testers: `npm run invite:create -- --count 10 --uses 1 --days 30 --note "beta wave 1"`.
   (`--uses` = people per code, `--days` = expiry.) To open sign-up to everyone later, set `INVITE_REQUIRED=false`.

## 6. Notifications (optional)
- `npm run push:keys` → put the two keys in Render as `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY`; `VAPID_SUBJECT=mailto:you@example.com`.
- Free Render sleeps: add a pinger (cron-job.org) calling `https://<service>.onrender.com/api/cron/tick?key=<CRON_SECRET>` every 5 minutes
  (`CRON_SECRET` is generated by the Blueprint: Render → Environment).

## 7. "Continue with Google" (optional)
Google Cloud Console → OAuth consent screen (External) → Credentials → **OAuth client ID → Web application**.
Authorised JavaScript origin: your web address. Put the client ID in Render as `GOOGLE_CLIENT_ID` (and the secret as
`GOOGLE_CLIENT_SECRET`, needed for Calendar sync). While the consent screen is in *Testing*, only listed test users can use it.

## 8. Android beta app
The app id is `dev.benedictisaac.winterarc.beta`, so it installs next to the personal app. It needs its **own signing key**:
```
keytool -genkeypair -v -storetype PKCS12 -keystore beta.keystore -alias winterarcbeta \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 beta.keystore    # copy this output
```
Keep `beta.keystore` and its password safe (you need the same key for every future update; never commit it).
GitHub → repo → Settings → Secrets and variables → Actions:
- Secrets: `ANDROID_BETA_KEYSTORE_BASE64` (the base64 text), `ANDROID_BETA_KEYSTORE_PASSWORD`, `ANDROID_BETA_KEY_ALIAS` (`winterarcbeta`)
- Variable: `BETA_API_BASE` = `https://<your-service>.onrender.com`

Push to `WinterArcBeta` (or run the workflow manually): a Release appears with `WinterArcBeta-1.0.N.apk`.

## 9. Drop file storage (optional)
Same as the personal app: a private Backblaze B2 bucket with the `S3_*` variables (`npm run storage:check`).
Files are stored under each user's own folder.

## Running tests
- `npm test` — unit tests always run. Integration tests (accounts, cross-user isolation, planner rules) need a MongoDB-compatible
  server and are skipped without one: `TEST_MONGO_URI=mongodb://127.0.0.1:27017 npm test`.
- GitHub Actions runs everything against a real MongoDB on every push to `WinterArcBeta`.
